# Política de segurança

## Reportar uma vulnerabilidade

**Não abra uma issue pública** para vulnerabilidades. Use o relatório privado do GitHub:
*Security → Report a vulnerability* neste repositório, e descreva o problema, os passos para o reproduzir e o impacto.

Respondemos assim que possível e coordenamos a divulgação depois de existir uma correção.

## Versões suportadas

Recebe correções de segurança a versão estável mais recente (`1.x`).

## O que nunca deve partilhar

Em issues, pull requests, logs ou capturas de ecrã, **nunca** inclua `api_key`, `public_key`, `security_credential`,
tokens `Bearer`, números de telefone reais ou respostas completas da API com dados de clientes. Se uma credencial
foi exposta, renove-a de imediato no portal do operador.
